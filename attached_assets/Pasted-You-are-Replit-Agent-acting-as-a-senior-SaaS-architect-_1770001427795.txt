You are Replit Agent acting as a senior SaaS architect + full-stack engineer. Build the MVP for an “AI Business Builder / Growth Engine” platform. The goal: one dashboard that orchestrates multiple external APIs (REST) through a clean connector system, and runs workflows like Naming → Domain availability → Brand kit → Website scaffold → Ready-to-post graphics.

IMPORTANT RULES
- Do NOT change the core concept: this is an orchestrator platform that plugs into many APIs over time.
- Build a production-minded MVP: strong project structure, env vars, validation, error handling, logging, and clear extensibility.
- Keep the UI clean and modern (Tailwind). No heavy design. Focus on functionality.
- Use TypeScript end-to-end.
- Prefer incremental deliverables: get auth + projects + connector skeleton working first, then implement one full workflow end-to-end.
- Provide “seed data” + demo mode so it runs without requiring all external API keys.

STACK
- Monorepo in one Replit workspace:
  - Frontend: Next.js (App Router) + TypeScript + Tailwind
  - Backend: Node.js + Fastify (TypeScript) OR NestJS (TypeScript). Choose Fastify for speed unless you strongly prefer NestJS.
  - DB: Postgres using Prisma ORM
  - Jobs/Queue: BullMQ + Redis (or a simple in-memory fallback if Redis not available)
  - Auth: NextAuth (Credentials) with hashed passwords OR Clerk if you must, but default to NextAuth.
  - API schema validation: Zod
  - Logging: pino (or built-in)

3) Connector System (the most important piece)
Create a /connectors folder in backend. Each connector must implement a standard interface:

interface Connector {
  key: string;                 // e.g., "domains.spaceship"
  name: string;                // human name
  authType: "none" | "apiKey" | "oauth";
  isConfigured(env: Env): boolean;
  test(env: Env): Promise<{ ok: boolean; message: string }>;
  run(task: ConnectorTask, env: Env): Promise<ConnectorResult>;
}

- Add a registry that lists available connectors and their configuration status.
- Create endpoints:
  - GET /api/connectors (list connectors + configured status)
  - POST /api/connectors/:key/test

4) Workflow Engine
- Workflows are multi-step sequences that call connectors and store outputs.
- Implement one workflow end-to-end:
  WORKFLOW: “Launch Step 1: Naming → Domain Check”
  Input: business idea fields from the Project
  Steps:
    a) Generate 50–150 name candidates (use an LLM connector if API key exists; otherwise use a strong local heuristic generator + curated patterns)
    b) Convert names into domain candidates (mostly .com, optional .ai)
    c) Check availability via a domain availability connector
    d) Save results to DB: nameCandidates, domainCandidates, availableDomains, finalSelection
  Output: UI shows only available domains + lets user favorite/select one.

- Add endpoints:
  - POST /api/projects/:id/workflows/naming-domain/run
  - GET  /api/projects/:id/workflows/naming-domain/status (job polling)
  - GET  /api/projects/:id/naming-domain/results

5) Domain Availability Connector (must be real)
- Implement a connector: domains.spaceship
- It should call a REST endpoint for bulk domain checks (availability + price). Read API key from env.
- If API key not provided, fall back to a “mock mode” that marks some domains available deterministically (so app works).

6) Brand Kit (MVP)

7) Website Scaffold (MVP)
